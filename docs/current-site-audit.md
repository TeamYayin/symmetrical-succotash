# Yayin AI Lab - Current Website Audit

## Executive Summary
This document provides a comprehensive technical audit of the existing Yayin AI Lab website repository. The most critical finding of this audit is a **technology stack misalignment**: the repository was assumed to be built with Gatsby, but it is actually built with **Hugo** (a Go-based static site generator) utilizing the **Bookshop** component library framework. No React or Gatsby dependencies are present in the project.

Before proceeding with any redesign or redevelopment, a strategic decision must be made: 
1. Continue the redesign using the existing Hugo/Bookshop stack.
2. Formally migrate the project to a React-based framework like Gatsby or Next.js, which will require a complete rewrite of all layouts and components.

## Current Technology Stack
* **Static Site Generator**: Hugo
* **Component Framework**: Bookshop (`@bookshop/hugo-engine`, `@bookshop/browser`)
* **Styling**: SCSS (compiled via Hugo pipes or precompiled) and vanilla CSS
* **Package Management**: npm (for Bookshop tooling) and Go Modules (for Hugo modules)
* **Content Management**: Markdown files with YAML frontmatter driving component composition

## Site Architecture
The site follows a standard Hugo directory structure with Bookshop integration:
* `assets/scss/`: Source styles.
* `component-library/`: Contains reusable UI components built with Bookshop.
* `content/`: Markdown files dictating the site's pages and blog posts.
* `layouts/`: Hugo HTML templates that frame the content.
* `static/`: Static assets including images, precompiled CSS, JS, and vendor plugins.
* `config.toml`: The primary configuration file for Hugo.

## Content Inventory
Content is heavily component-driven. For example, `_index.md` uses a `content_blocks` array in its YAML frontmatter to sequentially render Bookshop components (e.g., `big-hero`, `intro`, `about`, `counter`, `services`, `cta`) and passes data down to them. This provides a highly modular content authoring experience.

## Asset Inventory
* **Images**: Stored in `static/images/` and referenced via root-relative paths in markdown.
* **Styles**: SCSS in `assets/scss/` and CSS in `static/css/`.
* **Scripts**: Custom scripts in `static/js/`.
* **Vendor/Plugins**: Third-party libraries stored directly in `static/plugins/`.
* **Icons**: Evidence of themify-icons or similar icon fonts (`ti-desktop`, `ti-layers` used in content).

## SEO Inventory
* Configured centrally via `config.toml` (`title = "Yayin AI Lab"`, `baseURL = 'http://yayinailab.cc/'`).
* Page-level SEO (titles, descriptions) is likely handled in the frontmatter of individual markdown files and injected via `layouts/_default/baseof.html`.
* Hugo natively handles sitemaps at `/sitemap.xml` unless disabled.

## Performance Observations
* As a Hugo static site, baseline performance is likely extremely fast out of the box due to purely static HTML output.
* Unoptimized assets in `static/images/` or heavy plugins in `static/plugins/` could be potential bottlenecks.

## Accessibility Observations
* Requires visual and DOM inspection to confirm aria-labels, contrast ratios, and keyboard navigation support, particularly in the `nav.html` and `contact_form`.

## Responsive/Design Observations
* The content mentions "Modern & Responsive product design". The SCSS/CSS likely handles standard breakpoints.
* Bookshop components are designed to be responsive building blocks.

## Technical Debt
* **Vendor Plugins in Static Folder**: Storing third-party plugins directly in `static/plugins/` rather than managing them via npm can make updates difficult and bloat the repository.
* **Component Duplication**: Presence of `counter` and `counter_dark` might indicate a lack of flexible theming/props within a single component.

## Risks
* **Misunderstood Tech Stack**: Planning a Gatsby/React redesign on a Hugo/Bookshop codebase without realizing the discrepancy will derail project timelines.

## Things Worth Preserving
* **Content Structure**: The markdown files and frontmatter structure in `content/` are well-organized and platform-agnostic.
* **Component-Driven Approach**: The Bookshop setup provides an excellent modular authoring experience that should be replicated if moving to another framework.

## Things That Should Be Replaced
* If moving to Gatsby/Next.js: The entire `layouts/` and `component-library/` directories must be rewritten in React.
* `static/plugins/` should be migrated to a modern JS bundler approach (npm/yarn imports).

## Things That Are Unclear and Require a Decision
1. **Framework Decision**: Do we proceed with the Gatsby migration (requires full rewrite of layouts/components to React), or do we keep the current Hugo/Bookshop stack and redesign within it?
2. **Form Handling**: How does the `contact_form` currently process submissions? (e.g., Netlify Forms, Formspree, custom backend).
3. **Analytics**: Are there existing tracking scripts (Google Analytics, Plausible) embedded in the templates that need to be carried over?
